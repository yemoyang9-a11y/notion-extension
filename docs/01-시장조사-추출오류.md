## 0. 한 줄 요약

- 업계 공통 결론: **"모든 페이지를 100% 정확히 파싱하는 건 불가능"** (Notion 공식, Readwise, Obsidian 모두 문서에 명시). 그래서 다들 파서를 더 똑똑하게 만드는 것 못지않게 **실패했을 때의 탈출구(폴백 사다리)** 와 **회귀 테스트 코퍼스**, **"이 페이지 깨졌어요" 신고 경로**에 투자한다.
- Intact는 이미 Defuddle(Obsidian 클리퍼 엔진)을 쓰고 있어서 코드/수식 표준화 수준은 경쟁 제품 상위권이다. 문제는 **Defuddle을 거치지 않는 경로 2개**(선택 영역 클립, 복원 패스로 되살린 블록)와 **Notion API 제약 때문에 한 블록의 오류가 클립 전체를 실패시키는 구조**다.
- 한국 사용자 기준 가장 큰 구멍은 **네이버 블로그(iframe 구조)** 와 **외부 이미지 URL 규칙(pstatic.net referer 차단, webp/확장자 없는 URL)**.

## 2. Intact 코드 점검 — 위 유형별 현재 상태

`extractor.js`의 앱 코드(Defuddle 번들 뒤쪽 ~1,100줄)와 `background.js`를 읽고 대조했다. 파이프라인은:

```
[코드 페이지 전용 추출(GitHub blob / 순수 <pre> 페이지)]
  → 없으면 [선택 영역 HTML]
  → 없으면 [Defuddle parseAsync (8초 타임아웃 → 동기 parse)]
       → 이미지/링크 URL 정규화 (lazy attr, srcset 최대 해상도)
       → 복원 패스: 휴리스틱 본문 컨테이너와 비교해 Defuddle이 버린 블록·이미지를 되살림 (hidden 검사 포함)
       → 꼬리 정리: 끝에서부터 "저작권자/관련기사/구독하기…" 패턴 최대 30개 제거
  → HTML → Notion 블록 변환 (paragraph/heading/code/list/table/quote/image/equation/video/divider)
  → background: 페이지 생성(첫 100블록) → 100개씩 PATCH append, 350ms 간격, 429/5xx 재시도
```

## 3. 출시 전 권장 조치 (우선순위순)

### 3-1. 구조적 — "한 블록이 전체를 죽이지 않게" (A·B·N·U)
1. **블록 단위 격리 재시도**: 100블록 청크가 `validation_error`로 실패하면 → 에러 메시지의 `body.children[i]` 인덱스를 파싱해 해당 블록을 **강등**(이미지 → 북마크/텍스트 링크, 비디오 → 북마크, 불명 → 문단) 후 같은 청크 재전송. martian이 이 방식.
2. **전송 전 사전 검증기**(클라이언트): 이미지 확장자 화이트리스트, URL 길이 2000, 수식 1000자, rich_text 100개, 청크당 요소 수 ≤ 1000 · 직렬화 크기 ≤ 450KB (초과 시 청크를 더 잘게). 위반 블록은 미리 강등.
3. **부분 실패 표시**: 페이지가 이미 생성된 뒤 실패하면 "N/M 블록 저장됨 — Notion에서 열기" 로 안내하고, 재시도는 **같은 페이지에 이어서 append**(page id 저장) — 중복 페이지 방지.

### 3-2. 폴백 사다리 (Evernote/Obsidian 방식) (F·G·T)
4. **선택 영역·복원 블록도 Defuddle 표준화를 통과**시키기: 선택 HTML을 `<div>`에 넣고 Defuddle을 그 조각에 돌리거나, 최소한 Defuddle의 `codeBlockRules`/math 표준화 함수만 따로 적용.
5. **결과 품질 자동 판정**: 단어 수 < 100 (Readwise 기준), 블록 수 ≤ 2, 본문 대비 추출 비율이 낮음 → 팝업에서 "본문을 거의 못 찾았어요. 영역을 선택해서 다시 시도하거나 '전체 페이지'로 저장" 제안. 페이월 키워드(subscribe to continue / 로그인 후 이용) 감지 시 안내.
6. 최후 폴백 **북마크 모드**(제목+URL+og:image+설명)와, 여유가 되면 **스크린샷 모드**(`chrome.tabs.captureVisibleTab` → File Upload API).

### 3-3. 한국 사이트 (E·C·J)
7. **네이버 블로그/카페**: `executeScript({target:{tabId, allFrames:true}})` 로 모든 프레임에서 추출을 돌리고 가장 본문이 긴 프레임 결과를 채택하거나, `iframe#mainFrame`의 `src`(PostView.naver)를 감지해 그 프레임을 지정. SmartEditor ONE은 `.se-main-container .se-component` 단위로 `se-text/se-sectionTitle/se-quotation/se-code(.se-code-source)/se-image(.se-caption)/se-table/se-oglink` 매핑하는 전용 추출기가 가장 확실.
8. **pstatic.net 이미지**: 저장 전 확장 프로그램에서 `fetch`(같은 탭 컨텍스트라 Referer 자동) → **Notion File Upload API**(무료 5MiB/파일, 1시간 내 첨부)로 업로드. 이 경로는 D(만료 URL)·B(webp)까지 한 번에 해결하므로, "이미지가 외부 규칙을 통과 못 하면 업로드"를 기본 정책으로 삼는 게 낫다. `?type=w773` → `type=w2000`으로 원본 해상도.
9. **Tistory**: `data-ke-language` 우선, ColorScripter 표(`.colorscripter-code-table` 두 번째 `td`의 줄 div를 `\n`으로 연결, 푸터 링크 제거)를 코드블록으로 변환. Velog는 표준 Prism/KaTeX라 현재 코드로 대부분 OK.

### 3-4. 코드블록 세부 (H·I·J)
10. `Vo()`에서 `<br>` → `\n` 치환 후 textContent, 줄 래퍼(`[data-line], .line, .token-line, .cm-line`)는 줄마다 `\n`, 거터 선택자를 Defuddle 목록 수준(`.lnt, .lineno, .linenos, .rouge-gutter, .react-syntax-highlighter-line-number, td.gutter`)으로 확장.
11. `<pre>` 없는 코드 컨테이너(`.se-code-source`, `.colorscripter-code`, Monaco `.view-lines`, `div[class*="language-"]`)를 코드로 인식.

### 3-5. 운영 — 오류를 "모르는 채로" 두지 않기
12. **회귀 코퍼스**: Readability 방식으로 `tests/pages/<slug>/source.html + expected.json(블록 배열)`. 문제 페이지를 만날 때마다 스냅샷을 추가하고 CI에서 블록 변환기를 돌린다(추출기는 jsdom에서 동작 가능). 아래 4절이 초기 목록.
13. **팝업에 "이 페이지 결과가 이상해요" 버튼**: `debug: true`로 `debugHtml`을 받아 URL·추출 HTML·블록 JSON·에러를 묶어 GitHub issue 템플릿/폼으로 보내게. Readwise·Flylighter가 이걸로 파서를 키운다. (개인정보: 사용자가 내용을 확인하고 보내게, 자동 전송 금지)
14. **저장 후 요약 배지**: "32블록 · 이미지 4 · 코드 2 · 표 1 · 강등 1" 처럼 뭐가 들어갔고 뭐가 강등됐는지 보여주면 사용자가 즉시 눈치채고 신고할 수 있다.

## 4. 출시 전 테스트 코퍼스 (유형 × 대표 사이트)

각 항목은 "무엇이 깨질 수 있는가"를 노린 것. 결과는 Notion에서 직접 열어 육안 확인 + 블록 JSON 저장.

**코드**
- GitHub: blob(대용량 파일로 부분 로드), README(`.markdown-body`), Issue/PR 코멘트, Gist(임베드 iframe 아님, gist.github.com 직접), GitLab 파일 뷰, Bitbucket
- StackOverflow 답변(다중 코드블록+인라인 코드), Medium(코드 들여쓰기), dev.to, Hashnode
- 문서 사이트: MDN, Docusaurus(React 공식문서, `.token-line`), MkDocs Material(Pygments 줄번호), Sphinx/ReadTheDocs(`.linenos`), Hugo(Chroma `.lnt`), Jekyll(Rouge), Mintlify/Stripe docs(Shiki/rehype-pretty-code, 복사 버튼·파일명 헤더), Docs with tabs(언어 탭 → 여러 pre 중 hidden)
- 노트북: nbviewer, Google Colab(공유 링크), Kaggle 노트북
- ChatGPT/Claude 공유 링크(CodeMirror, Defuddle 전용 추출기 있음)
- **한국**: Velog(Prism+KaTeX), Tistory(`data-ke-language` + ColorScripter 표 글 하나 꼭), 네이버 블로그 코드블록(`.se-code-source`), Brunch(코드 없음, 이미지 갤러리)

**이미지**
- lazy-load: WordPress(`data-src`+placeholder), Medium(srcset), Substack(첫 장 외 로드 안 됨 이슈), 뉴욕타임즈/가디언
- 형식/URL: webp만 제공하는 사이트, 확장자 없는 CDN(Unsplash, imgix), 쿼리스트링 붙은 URL(`?type=w773`), 프록시 URL(`dthumb-phinf`), SVG 다이어그램, `<picture>` 태그
- 차단/만료: 네이버 블로그·뉴스(`pstatic.net`), notion.site 공개 페이지(S3 서명 URL), Google Docs 게시 페이지, Discord CDN
- `figure + figcaption`, 이미지 갤러리(네이버 imageGroup, Brunch gridGallery)

**표/리스트/수식**
- 위키백과(정보상자 colspan/rowspan, 수식 alttext, 각주), 나무위키(중첩 표, 접기), 위키독스
- 3단계 이상 중첩 리스트(Notion 도움말, GitHub README), 체크리스트
- arXiv HTML(ar5iv, MathJax v3, 번호 매긴 수식), KaTeX 블로그, 1,000자 넘는 긴 수식

**구조/동적**
- SPA: 트위터/X 스레드, LinkedIn 글, Threads, Reddit(Defuddle 전용 추출기), YouTube 설명란
- 무한스크롤/지연 렌더: Medium 긴 글, Notion 공개 페이지(블록이 뷰포트 진입 시 렌더)
- 페이월: NYT, 조선/중앙 유료, Medium 멤버 전용 — "잘린 본문"이 조용히 저장되는지 확인
- 로그인 필요: 네이버 카페, 카카오스토리, 사내 위키(Confluence)
- 쿠키 동의 오버레이(EU 사이트), 모달 위에 본문
- **iframe 본문: 네이버 블로그(필수), 네이버 카페, 구형 다음 카페**
- Shadow DOM(Salesforce/Lightning, 일부 Web Component 블로그)
- 한국 뉴스(네이버 뉴스 `#dic_area`, 다음 뉴스, 언론사 원문 — 꼬리 정리 오탐 확인), 짧은 글(꼬리 정리가 본문을 지우는지)
- 아주 긴 글(5,000블록 이상 → 50회 append, 진행률·중간 실패), 표 100행 × 여러 개(1,000 요소 한도)

**클립 방식별**
- 같은 페이지를 ① 자동 ② 영역 선택 ③ 컨텍스트 메뉴 로 각각 저장해 결과 차이 비교 (F 문제 재현용)
